## Главные выводы
1.  **Простота создания API:** С помощью Minimal API в ASP.NET Core можно создать полноценный веб-сервер буквально за несколько строк кода, в отличие от тяжеловесных фреймворков прошлого поколения.
2.  **Важность Middleware:** Порядок регистрации middleware критически важен. Они образуют конвейер (pipeline), через который проходит каждый запрос, и позволяют легко реализовать логирование, аутентификацию или обработку ошибок.
3.  **Автоматическая работа с JSON:** Фреймворк автоматически сериализует C#-объекты (включая анонимные и `record`) в JSON, что делает разработку REST API интуитивно понятной.

## Ответы на вопросы

**1. Чем Minimal API отличается от MVC в ASP.NET Core?**
*   **Minimal API:** Использует минимальное количество кода, идеален для микросервисов и простых API. Вся логика содержится в `Program.cs`, нет строгой структуры папок (Controllers, Models).
*   **MVC (Model-View-Controller):** Более тяжеловесный подход. Требует создания отдельных классов-контроллеров, моделей и представлений (Views). Лучше подходит для больших приложений с Web-интерфейсом (HTML).

**2. Что произойдёт, если поставить `app.MapGet(...)` до `app.Use(...)`?**
В этом случае маршрут будет обработан **до** того, как запрос дойдет до middleware. Middleware, написанные после `MapGet`, просто не успеют отработать для этого маршрута (или отработают, но после отправки ответа, что может вызвать ошибки). **Правильный порядок:** сначала `Use`, потом `MapGet`.

**3. Почему ASP.NET Core преобразует PascalCase в camelCase при сериализации JSON?**
Это сделано для соблюдения стандартов и конвенций разных языков:
*   **C# (PascalCase):** `FirstName` — стандарт именования свойств в .NET.
*   **JavaScript (camelCase):** `firstName` — стандарт именования переменных и свойств в JS/JSON.
Это преобразование обеспечивает совместимость API с клиентами на JavaScript/TypeScript. Этим поведением управляет `System.Text.Json` (настройка `PropertyNamingPolicy = JsonNamingPolicy.CamelCase`).

**4. Что означает код ответа HTTP?**
*   **200 OK:** Запрос успешно выполнен. Сервер вернул ожидаемые данные.
*   **401 Unauthorized:** Запрос требует авторизации. Клиент не предоставил валидные учетные данные (например, ключ `?key=secret` из лабораторной работы).
*   **404 Not Found:** Сервер не нашел ресурса по указанному URL. (Использовано в `MapFallback`).

**5. Чем `dotnet run` отличается от `dotnet watch run`?**
*   **`dotnet run`:** Запускает приложение один раз. Если вы измените код, сервер **не** перезапустится автоматически. Нужно вручную остановить (Ctrl+C) и запустить снова.
*   **`dotnet watch run`:** Запускает "смотрящий" (watcher) процесс. Он отслеживает изменения файлов в проекте и при их обнаружении автоматически перезапускает сервер (горячая перезагрузка), что значительно ускоряет разработку.
